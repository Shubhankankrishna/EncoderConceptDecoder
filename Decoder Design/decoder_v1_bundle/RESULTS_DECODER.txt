3. Readings
   - Proposed confined decoder = NCP-style stack in quality: carry exact 0.969 / 0.984 vs 0.969 / 0.984 (2 seeds each);
     loss +0.004 / +0.002 nats (tie band 0.02); filler loss equal. Slightly slower early (exact at 500: 0.68 / 0.67 vs
     0.72 / 0.73), equal by 1,000.
   - Core off -> 0 exact in every arm: the concept core is the only long-range route.
   - u carries the value (uOff -> 0); c_pred is barely used on these tasks (cOff 0.96 / 0.98).
   - Rejected: plan as a separate read stream (learned in 1 of 2 seeds; the other stayed at chance for 1,000 steps).
   - NextLat on the proposed decoder: no speed-up (exact at 500: 0.72 / 0.60 vs 0.68 / 0.67), final 0.984 / 0.953,
     loss +0.019 / +0.014 nats, filler +0.01. Neutral-to-slightly-negative here; these tasks have no planning component.
   - The core-off filler loss is NOT a skill measure: the null plan is off-distribution everywhere except document starts.
   - multi4 (4 facts x 3-token values): both arms at chance after 1,500 steps. Probes on the checkpoint:
     fact concept -> key 0.945, -> first value token 0.393; query concept -> key 1.000; core output at the query ->
     value tokens at chance (0.022 / 0.040 / 0.027). Bottleneck = core retrieval + concept identity capacity (encoder G-E1),
     upstream of the decoder. A first layout (value in the chunk after the key) was also at chance at 750 steps.
   - R1 = R8 = intact on these tasks: one retrieval, no depth needed. They do not test the loop.
   Caveats: CPU, d = 128, 1-2 seeds, synthetic tasks, stand-in core. Mechanics and routing are verified; language quality is not.
