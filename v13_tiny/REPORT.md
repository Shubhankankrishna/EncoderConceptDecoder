# V13-tiny-v2: 24-hour single-seed test (draft; results sections are filled in as runs finish)

Numbers in this file come from `REPORT_TABLES.md` (generated by `make_report.py` from the run logs and result
files). Every result is **one seed** and therefore exploratory (Dataset_v13.md §10.1). `DEVIATIONS.md` lists every
departure from v13_NOTES.md and Dataset_v13.md, written at launch.

## 1. What was built (`v13_tiny/`)

| File | Role |
|---|---|
| `grid.py`, `tasks.py` | The four reasoning families of Dataset_v13 §5 as frozen procedural generators with exact solvers: grid-rule induction (identifiable within a declared depth-2 grammar, parametric rules, new-parameter holdout), programs (arithmetic, lists, register programs, graphs), state tracking and binding (controlled English and compact records), explicit-goal planning (BFS-optimal, simulator). Ladders of 10 rungs per task type (8 trained, 2 test-only), S0 and the S1-S6 continual variants. |
| `tok.py` | One 2,048-entry tokenizer: 113 reserved structural tokens (single-token digits, colours, actions), byte-level BPE fitted on TinyStories and S0 renderings only. |
| `data.py` | Fixed 8 x 1,024 rows of whole documents, each starting at a multiple of 4; family-homogeneous batches under a token-quota scheduler (22.5% per reasoning family, 10% text); per-example normalised answer loss; the §7.3 curriculum by elapsed time; worker processes. |
| `model.py` | V13-tiny-v2 (below). |
| `tests_g0.py` | Float64 correctness tests (section 3). |
| `train.py` | Compiled training on MPS; AdamW (0.9, 0.95), LR 1e-3, warmup 200, cosine to 10% on elapsed time, NCP weight 0 -> 0.1 over the first 10% of time, EMA PQ codebook, atomic checkpoints, snapshots at every 10%. |
| `evaluate.py`, `final_eval.py` | Architecture-neutral evaluation: teacher-forced exact match (equal to greedy decoding for single-answer tasks), greedy decoding with a simulator for plans and a verifier for graph paths, floors, ladder areas, L50 fits, bootstrap intervals, the frozen Reasoning score, concept-path interventions, the new-parameter curve. |
| `cl.py`, `cl_eval.py` | Continual learning over S1-S6 from one base checkpoint: sequential LoRA, LoRA with reservoir replay, and V13's own method (RBF correction bank, wake / sleep distillation into gated LoRA); the continual matrix A[i, j] and its metrics. |
| `diagnostics.py` | §6.2's probe acceptance test, NCP accuracy per family, E2's loop at inference, GDN-2 output scale. |

## 2. The model

7,744,181 parameters (including the 1,048,448-parameter Engram table and the tied 2,048 x 128 embedding), d = 128
for L and G as asked, 4 heads.

| Module | Layout | Note |
|---|---|---|
| E1 | 2 x [S, S, S, F], Engram after the first S | S: window 8, partial RoPE, reads L, writes L and G; F: full attention, NoPE + temperature, reads L and G, writes G; GR read / scalar write / within-role mix after every layer |
| E2 | [M, M, M, F] looped R = 2 | M: Gated DeltaNet-2 (per-channel decay, erase and write gates), exact chunkwise form with document resets; workspace W from s0 with a per-loop embedding; reads {L, G, W}, writes W; exit G += s W |
| E3 | [S', S', S', F] | window 16, writes G only |
| Pool | per-channel softmax over each group of 4 | three sources (x, sg L_enc, G_enc), beta = (0.107, 0.107, 0.787) at init |
| C | 4 layers [self-attention over concepts <= g, window read of sg L_enc (16 tokens ending at 4g+3), FFN] | Delta-AttnRes over every sublayer with p_g as source 0; NCP head on u_g (4 x 32 PQ codes) |
| D | 6 layers [local attention on L_enc (window 16), concept read (release 4g+3, null entry, sink), FFN] | Delta-AttnRes with L_enc as source 0; tied head |

The user's constraints are met: d = 128 for L and G, more blocks than the design's tiny model (E1 doubled, C 4 layers
instead of 2, D 6 instead of 3), E2 recurrence 2, 7.7M parameters (between 2-3M and 10M).

## 3. Correctness (G0, float64, all pass)

- Exact reach: an edit 51 tokens back moves L_enc, 52 does not; with the concept read held fixed, an edit 66 tokens
  back moves the logits, 67 does not (design bound 53 / 68; see DEVIATIONS item 16).
- The whole model is causal (concept path included), and the concept path carries information beyond R_D.
- Packed documents are isolated bit-exactly (boundaries at 64, 100 and 128, both directions) and a document after a
  boundary equals the same document alone (to 1e-14).
- Release: concept g changes row 4g+3 and nothing before it.
- Chunkwise GDN-2 equals the token recurrence with document resets to 1e-15 (float64) and 5e-7 (float32).
- Every parameter receives gradient.

Two bugs were caught by these tests before training: the decoder's null entry was scored against the rotated query
(position-dependent; shift invariance failed by 0.65), and the GDN-2 decay sums crossed documents inside a chunk
(a 5e-15 numerical dependence).

## 4. Throughput engineering (the user asked for maximum throughput)

| Configuration (B x 1,024, fp32, MPS) | s / step | tokens / s | memory |
|---|---|---|---|
| eager, B = 8, no checkpointing (first version) | 70-110 (swapping) | 80 | 14.6 GB |
| eager, B = 8, checkpointing, factorised GDN-2 | 6.0 | 1,371 | 6.2 GB |
| compiled, B = 8, checkpointing | 2.53 | 3,234 | 5.4 GB |
| compiled, B = 8, no checkpointing | 2.37 | 3,464 | 10.9 GB |
| compiled, B = 16, checkpointing | 11.2 | 1,461 | 9.4 GB (memory pressure) |
| compiled, B = 4, checkpointing | 1.53 | 2,686 | 3.5 GB |

What moved the number: torch.compile (about 1.9x over eager here); rewriting GDN-2 from a pairwise per-channel decay
tensor to a factorised form with a log-depth scan over chunks (no (C x C x d) tensor, no 64-step loop); activation
checkpointing, which costs 7% but halves memory and keeps the 16 GB machine out of swap; fp32 (bf16 and fp16 are
slower on this MPS stack); SDPA for the full-attention layers. Two compiler problems had to be worked around: a fused
Metal kernel with more than 31 buffers (the Delta-AttnRes gradient fan-in; fixed by keeping the sources as a running
stacked tensor) and a non-finite compiled gradient for the key-norm gain of the attentions over concepts (removed).

Eager profile of one forward at B = 8 (ms): E1 336 (S layer 34, F layer 51, Engram 31), E2 562 (GDN-2 52 per call),
E3 157, concept module 90, decoder 401. E2's loop and the decoder's 18 Delta-AttnRes sublayers are the main costs.

## 5. Pre-registered readings (written 14 Oct 10:00, before any evaluation result existed)

One seed, so these are readings of this run, not claims about the architecture.

1. **Primary score.** Reasoning (Dataset_v13 §7.4) is reported with per-family parts. On its own it means little; it
   is the number tomorrow's baseline transformer is compared on (same data, tokenizer, budget and evaluation code).
2. **Is the concept path used?** (§10.4 interventions on the dev panels.) *Used* if zeroing or shuffling the concept
   read lowers teacher-forced exact match by at least 5 points absolute on at least two of the eight task types.
   *Not used* if every drop is under 2 points; that would be a negative result for the design's central mechanism.
   A text-NLL rise far larger than the reasoning drops would mean the path carries language statistics instead.
3. **Does u_g predict ahead?** (§6.2 acceptance test.) An MLP probe on u_g must beat the same probe on its input p_g
   by at least 5 points on next-group PQ codes; reported per family, pass or fail.
4. **Is E2's second loop used?** Exiting E2 after loop 1 at inference must cost at least 3 points on some task
   type for loop 2 to count as carrying computation. (The model was trained at R = 2 only, so this does not say what
   an R = 1 model would learn.)
5. **Continual learning.** v13's method *helps* if its forgetting is lower than seq's and its S0 retention before
   the return phase (state S5) is higher, with paired 95% intervals excluding zero, while its acquisition gain
   is at least half of seq's. Replay (20%, 1,000 rows) is the reference bar: below replay on final average means the
   method is not yet competitive with the simplest baseline. Any other outcome is reported as it is.
6. **Nothing is re-run or re-tuned after seeing a result.** A crash is fixed and the stage is re-run in full; this is
   recorded in DEVIATIONS.md.

## 6. Results

Filled on 15 Oct 2026 from 06:53 IST, from `REPORT_TABLES.md` (regenerated at 06:51) and the run logs. **At the
07:30 deadline the base run, the base test and the diagnostics are complete; the continual stage is not.** Sequential
LoRA finished all six phases; V13's own method finished S1-S3 and had been in S4 since 02:40; replay and the continual
matrix had not started. Reading 5 therefore has no result yet (section 6.6). One seed throughout: every line below is
"observed, seed-unreplicated".

### 6.1 Base run and throughput

12,474 steps and 97.86M processed tokens in 10.98 h of training time; no skipped updates. Throughput: median 2,519
tokens/s over 50-step intervals and 2,471 tokens/s on average (tokens over training time), against 3,234 in the
launch benchmark (section 4). The gap is attributed to side jobs at background QoS during the run (DEVIATIONS item
34) and to thermal throttling on this fanless machine. Losses fell in every family; text NLL went from 4.85 (0-10%)
to 2.80 (90-100%).

### 6.2 Reading 1: the primary score

**Reasoning = 0.283.** Per family: grid -0.008, prog 0.344, state 0.470, plan 0.325. Text NLL 2.800 nats/token.

- **Grid-rule induction did not learn.** The ID areas of grid1 (0.045) and grid2 (0.019) sit at their floors. The
  new-parameter curve stays at or below 0.018 over all ten snapshots, and the grid challenge panels sit at their floors.
- **Programs and planning are solved at short rungs and fall with length.** Rung 0 to rung 7: list 0.95 to 0.21,
  registers 1.00 to 0.11, plan 0.99 to 0.02, arithmetic 0.49 to 0.10.
- **Graph and state tracking hold above floor on every rung, the test-only rungs included.** Extrapolation areas are
  0.33 and 0.54; plan's test-only rungs are 0.
- **List composition is barely above floor:** 0.047.

This is the number the baseline transformer will be compared on.

### 6.3 Reading 2: is the concept path used? **Used.**

Rule: the path counts as used if zeroing or shuffling the concept read lowers teacher-forced exact match by at least
5 points on at least two of the eight task types.

| Intervention | Task types dropping ≥ 5 points | Text NLL change |
|---|---|---|
| zero | 5 of 8: list 28.1, plan 27.4, arithmetic 8.6, registers 5.1, state 5.1 | +0.125 nats |
| shuffle | 4 of 8: list 34.8, plan 33.6, arithmetic 6.6, registers 6.2 | +0.046 nats |
| batch mean | 4 of 8 (list and plan 31.6) | +0.032 nats |

The text-NLL rises are small next to the reasoning drops, so the path carries task information, not mainly language
statistics. Graph and grid are unaffected (grid is at floor).

### 6.4 Reading 3: does u_g predict ahead? **Fails in all four families.**

The MLP probe on u_g against the same probe on p_g, on the next group's codes: grid +0.1, prog +1.2, state +0.5,
plan +3.2 points, against a 5-point bar. Both probes are high (0.78-0.99), so the next code is about as predictable from
the concept module's input as from its output. The NCP head's accuracy is 0.79-0.97, and code usage perplexity is 24-26
of 32.

During training (14 Oct, about 15:50, step 6,898) the head was seen predicting one tuple for every group. The run was
not changed (user decision). The post-hoc analyses of this, which are not pre-registered readings, are in
`v14_design/checks/checks.json`: at 50% of training the head was below copy-current in all five families. They
motivated V14 (`v14_Architecture.md`).

### 6.5 Reading 4: is E2's second loop used? **Not used.**

Exiting E2 after loop 1 changed teacher-forced exact match by 0.000 on all eight task types, and answer NLL by at most
0.0005, on the dev panels. The bar was 3 points on some task type, so loop 2 carries no computation that reaches the
answers in this run. Its GDN-2 layers do write: output RMS is 0.10-0.21 in both loops.

### 6.6 Reading 5: continual learning. **No result: the stage was stopped in S4.**

**Sequential LoRA (21:27-00:36, all six phases).** Loss on the incoming rows, first ten batches against last ten:

| Phase | S1 | S2 | S3 | S4 | S5 | S6 |
|---|---|---|---|---|---|---|
| first 10 batches | 1.11 | 3.92 | 0.82 | 5.50 | 2.67 | 0.91 |
| last 10 batches | 0.46 | 0.83 | 0.30 | 1.36 | 0.85 | 0.42 |

This is acquisition on the training rows only. Forgetting and retention need the matrix.

**V13's method, S1-S3.**
- Gates opened on 61%, 76% and 65% of their own phase's inputs, and on 32%, 25% and 41% of the reference inputs.
- Sleep distillation's KL fell to 0.003-0.007 in every phase.
- The correction bank never overflowed (160K-184K writes per phase).

The phases got slower and used more memory:

| Phase | Time | MPS driver memory |
|---|---|---|
| S1 | 1,031 s | 7.1 GB |
| S2 | 2,009 s | 9.5 GB |
| S3 | 4,386 s | 12.8 GB |
| S4 | started 02:40:38; stopped unfinished at 13:48:47 (11 h 08 min) | — (process footprint about 20 GB at 13:44) |

The measured cause: each fitted gate evaluates two 4-component diagonal Gaussian mixtures on the input of every adapted
projection, materialising tensors of rows x 4 x width. With two fitted gates, one forward took 6.30 s against 3.51 s
without adapters (02:26, under contention). Each phase adds a fitted gate, and from S3 on the machine was in swap
(4.6-6.7 GB of up to 7.2 GB; 7.0 GB of 8.2 GB at 13:44, with 0.1 GB of memory free).

**Not run:** replay, and `cl_eval` (the matrix A[i, j], forgetting, S0 retention before the return phase, the paired
intervals). So reading 5 is the pre-stated "did not finish" outcome (DEVIATIONS items 37 and 38).

Nothing in the run was changed while it ran (reading 6). An intervention was prepared at 02:52: stop the run and resume
S4-S6 with an algebraically identical form of the gate's density ratio, which changes 28 of 6,832,128 decisions on V13's
own fitted gates. At 13:48 on 15 Oct the user reported the laptop had become choppy. Rather than resume, the user chose
to stop the stage and start V14-tiny (DEVIATIONS item 38). The S1-S3 adapter states and the unrun resume script
(`cl_resume_item38.py`) are kept, so the stage can be finished later.

### 6.7 Summary of this run

- The concept path is used: removing it costs 5-35 points on list, plan, arithmetic and registers.
- What it computes does not predict the next group beyond its own input (reading 3).
- E2's second loop is inert at inference.
- Grid-rule induction did not learn at 7.7M parameters in 11 hours.
- The continual reading has no result: the stage was stopped in S4 on the user's decision (DEVIATIONS item 38).
