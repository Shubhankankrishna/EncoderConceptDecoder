Research model · 25.05M compute parameters · Apple M2 · PyTorch MPS

A language model that has to think in concepts to see far back

The token-level decoder can only look at the last 70 tokens. Anything older must travel through a separate concept stream: every 4 tokens are compressed into one concept, a small module reasons over the concept sequence, and it hands the decoder a plan. If the model recalls a fact from 400 tokens ago, the concept stream carried it.

The three parts

Read, think, write. Each part is a separate module with its own parameter budget.

1

Encoder reads & compresses

Reads the tokens with two streams: a local one that sees only 63 tokens back (the decoder may read it) and a global one that sees the whole document (only used to build concepts). Every 4 tokens become one concept vector.

8 layers15.5M params+ 50.3M n-gram memory

2

Concept module thinks ahead

Runs one shared attention layer R times (1–4) over the concept sequence, then predicts the codes of the next concept from a 48 × 128 codebook. Its output is the plan for the decoder.

1 layer × R2.06M params1 concept per 4 tokens
See the concept module →

3

Decoder writes the next token

Predicts each next token from the local stream (last 70 tokens) plus its own plan. It is “confined”: no position can read another position's plan, so long-range knowledge can only come from the concept module.

4 layers7.53M paramsreach 70 tokens

The evidence

How we know the concept stream is doing the work.

Swap the plan, and long-range recall collapses

The long-range probes hide an answer 128–420 tokens back, out of the decoder's reach. Each probe is scored twice: normally, and with the plan swapped for another document's (plan swap). High accuracy normally and chance when swapped means the answer came through the concepts.

    Concept module v2

    Six proposed concept cores (4 layers, d 256, FFN 1024, full attention, recurrent), each built on a different mechanism that makes extra passes matter, scored against today's module. Nothing here changes the running training.

    Why these designs. The papers agree on only three ways to make extra passes matter: train with many random pass counts (D1, D4), distil short routes toward the long one (D2, LoopFormer), or detach the carry between groups of passes and supervise every pass (D3, D5). Each design is anchored to a different one of these, so the score compares mechanisms, not residual or FFN tweaks; D4 adds pass-dependent experts, D5 a leak-bounded set of candidate plans for next chunks that have several valid continuations. D6 (your request) combines D3's detached, fully graded windows, LoopFormer's distillation toward the endpoint in the final window (from D2) and D4's experts routed on the state; it ties D3 on the rubric (70.0 vs 70.5) because it adds moving parts, and three ablations (E16, A4, A2) decide between them.

    Model v2 · design, not trained yet · 18.83M compute parameters

    v2: a balanced thinker. Smaller encoder, a real concept module, a decoder that must plan

    Same three-part idea as v1: tokens are compressed into concepts, a module reasons over them, and a confined decoder writes. v2 fixes what v1 taught us. At d = 256 the concept module grows from 8 % to 42 % of the parameters (a looped D6 core with 16 experts), the Engram memory grows to 80M lookups, and NextLat pushes the decoder's state and therefore its plan to be a belief state.
