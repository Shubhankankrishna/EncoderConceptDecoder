Encoder → concept → decoder · version 9

Give every reasoning step a committed, searchable choice

Every earlier version handed the decoder an average of the possible next concepts. You cannot branch a search over an average, and you cannot reinforce it. V9 replaces it with K discrete codes per concept step (H-NCP). Each code commits to one possible next concept, and a small selector learns which code will win. The code is the MCTS action. The selector is both the search prior and the RL policy.

With K = 1 the objective is exactly V8's, so the main claim changes a single axis.

The question asked

Can the decoder leave the search loop?

Why it might work

  • One concept is exactly one hop: [COL, TO, NODE, SEP] is one 4-token chunk.
  • The transition is an in-context lookup over edge-concepts that the core already attends to.
  • NCP already makes self-feedback 18× less harmful on graph data than no NCP (+.048 vs +.891 nats).
  • A decoder-free child costs about 5 block-positions against 28 for a token child.

How it could fail, each with a gate

  • Rolled-forward concepts drift over N steps (G2.3a).
  • Predicted hops decode to illegal moves (G2.3b).
  • The value head is too inaccurate to replace the verifier (R5, AUROC ≥ .80).
  • On the M2, kernel launches dominate, so the cheaper nodes don't save real time (§9.3).

What V9 measures

  • A curve, not a yes/no: decode and re-ground every R ∈ {1, 2, 4, ∞} steps. R = ∞ is your exact proposal.
  • Main competitor: token-level tree search over the same hops, same weights, equal wall-clock.
  • Latent steering record so far: 0 wins in 4 against a simpler search.
  • Pre-registered confidence that R = ∞ wins on hard14: ~25%.

§4.2 · exact indexing

One concept is one step, and the plan lands one chunk later

The plan from chunk j is first exposed at logit position 4j+3, so it steers the tokens of chunk j+1. The last prompt chunk therefore picks hop 1. In general, the action for hop h is the code chosen at chunk h−1.

Edges are [NODE, COL, NODE′, SEP], hops are [COL, TO, NODE, SEP], and the terminator is [DONE, SEP, SEP, SEP]. With 3 colours, the colour is the only free choice in a hop.

Search signal versus gate procedure

The 73-candidate nearest-chunk decode (≈876 block-positions) is the ground truth for gate G2.3(b). Search never uses it. Search reads two cheap heads on u⁽⁰⁾: value V_ψ and terminal τ_ψ. Iteration 0 has neither head, so it runs at R = 1 with every node decoded.

§10 · Local Support Learning

A local gate protects old skills only where inputs separate

LSL opens a phase's adapter where Φpos (this phase's inputs) is denser than Φneg (generic inputs). Where the new and old inputs overlap, the newest update wins by design. V8's bind phase sat in exactly that overlap. V9 measures separability first (gate G6.0) and keeps bind as a pre-registered negative control.

Synthetic 2-D illustration of a JL-projected input space. The shaded region is where the gate opens (Φpos > Φneg). The hit rate is computed live: the share of old-task points (navigation and text) that fall inside the open region.
