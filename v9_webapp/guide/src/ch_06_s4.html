Learning from a right-or-wrong checker

Can the model get better at choosing among its guesses by playing puzzles and learning from which choices the checker approves?

In one breath

  • Post-training means learning from feedback after the main training. Here the only feedback is the verifier saying right or wrong.
  • The main method is expert iteration: search finds good choices with the verifier's help, and then the quick instincts (the selector and two tiny judges) are trained to reproduce them. Repeat four times.
  • It is compared, with the same puzzles and the same budget, against three standard methods. The result is reported either way.

Why there is no separate fine-tuning step

Many pipelines first fine-tune on worked examples and then use reinforcement learning. Here, the training data already contains verified worked examples: the puzzle answers are trained response-only from the very start. A separate fine-tuning stage would only repeat that. What is new in S4 is learning from a checker on puzzles the examples do not teach well, mostly the hard ones.

The primary method: expert iteration

Imagine a chess player who spends a long time analysing a position, makes the move that analysis points to, and keeps notes. After many games they train their instinct to suggest what the analysis would have concluded, so next time the instinct is better and the analysis starts from a better place. That is expert iteration. The famous AlphaZero uses the same idea.

What each trained part learns to predict

After a search, we know how often each code was visited. A code that looked promising was tried many times. We train the selector so that its odds match those visit shares. In plain terms, we copy the slow search into the quick instinct.

The two tiny judges are single linear layers (129 numbers each). The value judge predicts whether the answer will be correct, from the current position. The stop judge predicts whether stopping is legal here. They let the search score a branch without paying for a full rollout. They are only trusted if they pass their own gate, checked on held-out positions: the value judge needs an AUROC of at least 0.80 on complete answers and 0.70 on intermediate and imagined ones, and the stop judge needs 90% recall with at most 2% false positives on imagined states. If a judge fails, search falls back to verified completions, which cost more.

Is it a fair fight?

Three standard methods start from the same promoted checkpoint, with the same puzzles, the same number of verifier calls and the same time cap. Token RFT samples complete answers, keeps the verified ones and fine-tunes on them. Token GRPO is a popular policy-gradient method on the same adapter. Selector REINFORCE is policy gradient on the selector. The first two use a small trainable adapter (LoRA) on the decoder instead of the codes.

The capacity is not equal, and the project says so openly.

GradCuit and the sign of the reward

GradCuit is a test-time method. When an answer fails, it nudges one code vector, up to ten times, to make the rejected answer less likely, and then writes again. One detail is easy to get wrong. If the reward were simply 1 for correct and 0 for wrong, a wrong answer would multiply the whole gradient by zero and the method would do nothing at all. So the reward is set to o − 1: 0 when accepted, −1 when rejected.
