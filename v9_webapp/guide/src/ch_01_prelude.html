Chapter 1 · the basics

Five ideas you need first

Tokens, guessing, surprise, walking downhill, and blocks. If you know these, every later chapter is readable. If you already know them, skip to the next chapter.

1. A computer only understands numbers

A computer cannot read the letter "c". It can only do arithmetic. So the first step of any language model is to turn text into numbers.

The usual way is to cut the text into pieces called tokens and give each piece an ID number from a fixed list called the vocabulary. Our models use a vocabulary of 2,048 pieces. Common words get a piece of their own. Rare words are cut into smaller pieces.

After this step the model never sees letters again. Each ID is swapped for a list of 128 numbers called a vector. Picture a vector as the coordinates of a point on a map with 128 directions. Pieces that behave alike end up close together. The model's whole job is to move and mix these points until the last one lands near the right next piece.

2. A language model is a guessing machine

A language model has one job. Given the tokens so far, it gives every token in the vocabulary a probability of coming next. The probabilities add up to 1. To write, it picks one token from that list, adds it to the text, and repeats.

Pause and think

Look at the "fork" situation: left and right are almost equally likely, and both are fine. If the model always picks its favourite, it hides the other good answer. Remember this picture. It comes back in the S2 chapter as the main reason S2 exists.

3. Learning means being less surprised

To train a model we need a score for how wrong it is. The standard score is its surprise at the real answer. Take the probability the model gave to the token that actually came next, and compute minus its natural logarithm. That number is the loss.

If the model was sure and right (probability 1), the loss is 0. If it gave the true token only 1 chance in 100, the loss is 4.6. A model that knows nothing guesses evenly over 2,048 tokens, which gives a loss of 7.6. When you read about a text loss falling from about 7.7 to about 2.9, that is a model going from clueless to usefully surprised-less.

4. How the guessing improves: walking downhill

The model is a large pile of numbers called parameters (or weights). Our main model has about 2.4 million. Training adjusts them so that the loss goes down.

For each parameter, calculus tells us whether raising it would raise or lower the loss. That slope is the gradient. We nudge every parameter a small step in the direction that lowers the loss, then repeat millions of times. This is gradient descent.

Analogy

You are on a foggy hillside and want the valley. You cannot see it, but you can feel the slope under your feet, so you step downhill. The size of your step is the learning rate.

Idea

Where you start changes where you end up. A training run starts from random numbers, and the dice roll that sets them is called the seed. The same recipe with a different seed can behave very differently. You will see a striking real example in S1, and it is the reason every comparison in this project uses at least two seeds.

5. Inside the guesser: attention and blocks

Between the vectors that go in and the probabilities that come out sits a stack of layers called blocks. Each block does two things.

  1. Attention: look back.

    Every position looks at the earlier positions and decides which ones matter for it. It collects a weighted blend of what it finds. It is only allowed to look backwards, because looking ahead would be cheating on a guessing task. This is called causal attention.

  2. Feed-forward: think.

    Each position then thinks on its own about what it gathered, using a small network.

Both steps add their result to the vector instead of replacing it. This means nothing is lost along the way. A model with ten blocks does "look, then think" ten times.

Small on purpose

Chat assistants have dozens of blocks and vectors with thousands of numbers. Ours has 10 blocks and vectors of 128. It trains in hours on a laptop, which lets us run many careful experiments. The price is that some things that work at large scale may not show up here. The project says so openly wherever it matters.

Words you will see in every chapter

Parameter
One adjustable number inside the model. Training changes them.
Trainable and frozen
A trainable part is adjusted during training. A frozen part is locked: it is used, but never changed. Several experiments freeze most of the model and train only a small piece.
Checkpoint
A saved copy of all parameters at some moment.
Seed
The dice roll that sets the starting parameters and the data order. Same recipe, different seed, can mean a very different result.
Control (baseline)
The same setup with the one thing under test switched off. Without it, a result cannot be explained.
Development set
Practice puzzles used while building, to make decisions. Looking at them is fine.
Sealed test set
Puzzles locked away and opened once at the end. If you peek early, you start tuning to them without noticing.
Verifier
A small ordinary program that checks whether an answer is correct. It is not a model, so it cannot be fooled by fluent nonsense.
