Glossary

Every term in this guide, in plain words, in alphabetical order.

α (alpha)
The weight that says how much the next-concept task counts in the total loss. In S1 it is 0 at first, then ramps to 0.1.
Adapter
A small trainable add-on attached to a frozen matrix, so new learning does not change the original numbers. See LoRA.
Attention
The step where each position looks at earlier positions and takes a weighted blend of what it finds.
AUROC
A score from 0.5 (no better than guessing) to 1 (perfect) for how well a judge separates right answers from wrong ones.
Baseline, control
The same setup with one thing switched off or replaced, so a difference can be traced to that one thing.
Best of m
In S2 training, draw m codes using the selector's odds and let the closest one steer the writer.
Block
One round of "look back, then think" (attention, then feed-forward), with each result added to the vector it came from.
Checkpoint
A saved copy of all of a model's parameters.
Chunk
A group of four tokens. On GraphNav, exactly one road of the puzzle or one hop of the answer.
Closed loop
Training in which the concept core sometimes reads its own earlier guesses instead of real concepts.
Code
One of K learnable vectors that nudge the last concept block toward a different guess. Also called a hypothesis code.
Codebook, stickers
A fixed set of reusable vectors. A guess is built as a weighted blend of them.
Concept
The summary vector of one chunk: the average of its four token vectors, rescaled.
Concept stack, concept core
The blocks that read only concepts, not tokens. They reason one step at a time.
Continual learning
Learning tasks one after another without forgetting earlier ones.
Dead code
A code that almost never wins, and so never learns. S2 restarts such codes.
Decoder
The blocks that write tokens. Also called the writer.
Development set
Puzzles used while building, to make decisions. Compare sealed test set.
Distillation
Training a model to match another model's outputs. In S2, a temporary pull of the plain path toward the teacher.
ECE
Expected calibration error: how far a model's stated odds are from how often it is actually right.
Embedding
A vector of numbers that stands for a token.
Encoder
The blocks that read the real tokens and give each a richer vector.
Expert iteration
Search finds good choices, then the quick instincts are trained to copy them, and the loop repeats.
Frozen
Used, but never changed during training.
G(R)
One search for the whole puzzle that decodes and re-reads every R steps.
Gate (pre-registered)
A pass or fail rule written down before the run, with a pass zone, a partial band and a fail zone.
Gate (LSL)
A switch that turns an adapter on only for inputs that look like the data it was trained on.
Gradient, gradient descent
The slope of the loss with respect to a parameter, and the habit of stepping a little downhill along it, over and over.
GradCuit
A test-time method that nudges one code vector to make a rejected answer less likely.
GraphNav
The exam: find a route through a map of one-way roads in three colours.
GRPO
A standard policy-gradient method for improving a model from reward, here used as a baseline.
H-NCP
Hypothesis-conditioned next-concept prediction: S2's idea of K committed guesses with a selector.
hard10, hard14, long18
Harder puzzle suites on 10, 14 and 18 towns. The larger two are bigger than any training puzzle.
IMAG
A search that imagines the whole route and decodes only the final winner.
K
The number of codes (hypotheses). K = 1 means no codes, which is the older method.
Learning rate
The size of each downhill step in training.
LoRA
A way to add a small, low-rank correction to a frozen matrix. Rank is how thick the correction is.
Loss
A score of how wrong the model is. Usually the surprise at the true answer. Lower is better.
LSL
Local Support Learning: an adapter per new task, each with a gate that opens only for familiar inputs.
MCTS
Monte Carlo tree search: try branches, remember how each did, and favour the promising ones.
McNemar test
A test for two arms on the same puzzles, using only the puzzles where exactly one of them succeeded.
Mode
One of several distinct possible answers. A fork has two modes.
NCP
Next-concept prediction: guessing the concept of the next chunk before it is written.
Nats
The unit of loss when the natural logarithm is used.
Parameter
One adjustable number inside the model.
Port
A second, plain vector sent alongside the guess to the decoder, scaled by a learned knob.
PrefixLM
Letting each prompt position look at the whole prompt, in both directions.
Pre-registration
Writing down predictions and pass or fail rules before seeing results.
Product quantization
Describing a vector by choosing from a small menu separately for each slice of it.
PUCT
The rule that picks which branch a search tries next, from its average result, the prior, and how rarely it was tried.
Receding horizon, RH(H)
Search up to H steps ahead, commit one step, then search again from the new real position.
REINFORCE
The simplest policy-gradient method.
RFT
Rejection-sampling fine-tuning: sample answers, keep the verified ones, train on them.
Sealed test set
Puzzles locked away and used once at the end.
Seed
The dice roll that sets the starting parameters and the data order.
Selector
A small layer that predicts the odds that each code is the right one.
Separability
How well the inputs of a new task can be told apart from the inputs of old tasks. It limits how much a gate can protect.
Teacher, student
In S2, the frozen S1 model and the new trainable concept core that learns from it.
Token
A small piece of text treated as one unit, with an ID number.
Value judge, stop judge
Two tiny linear layers: one predicts whether an answer will be right, one predicts whether stopping is legal here.
Vector
A list of numbers. Think of it as a point on a map with many directions.
Verifier
A small ordinary program that checks an answer exactly.
Winner-take-all
Training rule where only the closest of several guesses gets the full lesson, so the guesses specialise.
