Several sharp guesses instead of one blur

When a step has several valid next moves, can the model keep a few distinct, committed guesses instead of averaging them into mush, and can it learn which one to try?

In one breath

  • S1's guess of the next concept is an average. When two moves are equally good, the average points at neither.
  • S2 gives the model K "what if" codes. Each code commits to one possible next concept, and a selector learns the odds that each one is right.
  • We compare K = 8 against K = 1 on two seeds. The first half (dense core) is running now. The second half (recurrent core) is queued after S6's first experiment.

The problem: the average of two good answers can be bad

Go back to the fork from the basics chapter. A friend asks which way to turn. Half your sources say left and half say right. If you answer with the average, "walk straight ahead", you walk into the wall.

S1's guess of the next concept is trained with squared distance. Mathematically, the best single guess under squared distance is the average of everything that could happen. On GraphNav the true next concept depends on which colour the walk takes, and often several colours are equally fine. The average of those concepts is the concept of no real road.

Watch it happen. Three real options are marked. One guess is trained by gradient descent on examples from them.

Analogy

A group of art students is asked to paint "a face". If each student is graded on how close their painting is to every reference photo, all of them paint the same blurry average face. If each reference photo is assigned only to the closest student, the students specialise and paint distinct, sharp faces.

Step 1: give the last concept block K codes

We do not build a new network. We reuse the last concept block and run it K times, each time with a different learnable code added to its input. A code is just a short vector of numbers, like a dial setting. Each setting nudges the block toward a different answer.

This is cheap. The block's keys and values come from the plain input, so one pass over the sequence serves all K codes. At K = 8 the extra cost is about 29% more block-work, and only 3,208 new parameters.

Safety net

With K = 1 there are no codes at all, and with the closed loop off the training is exactly V8's. A test checks that the loss, every gradient and one optimiser step match V8 to one part in a million. That is how S2 is "nested" in V8: K = 1 is the old method, so any difference is caused by K.

Step 2: winner-take-all training

For each position we compare every hypothesis with the true next concept. The closest hypothesis gets a full lesson. The others get a lesson of only 5% strength. The 5% keeps losers from being abandoned, so they can still move toward a mode later. Without it, a code that loses early may never win again.

Step 3: a selector learns the odds

Having K guesses is no use if you cannot tell which to try. A small linear layer, the selector, reads the plain row and predicts how likely each code is to be the winner. Its training target is a soft version of "who won": codes that nearly tied share the credit, so near-ties do not become noise.

Now the writer, the frozen decoder, needs a plan to follow during training. Which code's guess should we hand it? There are three options, and the choice matters.

The main arm uses m = 2: draw two codes using the selector's odds and let the closer one steer the writer. It is a middle road. It sends the lesson to a code that already explains the truth well, as winner-take-all does, but it still only offers codes the selector would actually offer at test time.

Step 4: a frozen teacher and a trainable student

S2 does not retrain the whole model. It takes a finished S1 model, the teacher, and freezes the encoder, the decoder, the codebook and the sticker heads. Only a fresh copy of the concept stack, the new codes and the selector are trainable. Look at which parts are grey (frozen) in the 3D scene below.

The teacher also supplies a safety rope: for the first 10% of updates the plain no-code path is pulled hard toward the teacher's outputs, and the pull fades to zero by 30%. This keeps the model from drifting before the codes have settled.

Which teacher?

Seed 911 learns from S1's seed-902 model. Seed 912 learns from V8's seed-811 model, because S1's other seed failed the competence gate. So the two S2 seeds really are different teachers, and arms should be compared within a seed.

Step 5: practise on your own handwriting

When search runs, the concept stack will read its own guesses instead of real concepts. If it has only ever read real ones, that is like a driver who has only practised on a simulator and is then put on a real road. So, in 25% of training sequences, a short run of 1 to 4 chunks gets its input replaced by the model's own committed guess. The grading target stays the real concept.

Step 6: when a hypothesis never wins

Winner-take-all training has a known failure: a code that never wins never learns, so it is wasted. The project handles this with the 5% loser lesson, a restart rule, and logging. The rule: every 500 updates, any code whose share of wins fell below one in ten K is restarted as a noisy copy of the most-winning code.

How we decide: four gates in plain words

All thresholds were written down before the first S2 run. Each gate asks one question. They are judged on the development puzzles, never the sealed ones, with 95% bootstrap intervals. Each gate is judged per seed, and passing needs both seeds to pass.

G2.1

Authority: does the code steer the writer?

(a) If we pick the best code using the answer, is the loss on the puzzle tokens at least 0.05 nats lower than K = 1? (b) If we swap the chosen code for each other code at the last prompt chunk, does the first road change in at least 30% of cases, and is the new road legal in at least 90% of those?

pass: ≥ 0.05 nats and ≥ 30% / ≥ 90% · fail: no gain, or < 15% / < 70%
G2.2

Calibration: can the odds be used without peeking?

Four checks: the loss with one drawn code and with the top code stays close to K = 1; the selector's top two choices cover the right next move almost as often as the best possible selector could; its stated odds match how often codes win; and greedy puzzle success is not worse than K = 1 by more than 2 points.

pass: ≤ +0.05 / +0.02 nats, coverage ≥ 90% of the ceiling, error ≤ 0.05, ≥ K/2 live codes, success within 2 points
G2.3

Imagined versus executed

Take N steps by following codes in the model's head, then take the same steps by actually writing each one. Do the two end up making the same next decision, and are the written steps legal?

pass at every N up to H: agreement ≥ 90%, legal ≥ 95%. The largest passing H is the lookahead depth S5 may use.
G2.4

Execution consistency: what does each code write?

For a given state, decode every code. Do they write at least two distinct legal roads when two roads make progress? Is there always some code that makes progress? Is a code's guess closest to the road it actually writes?

pass: branching ≥ 80% and coverage ≥ 95%. The guess-matches-road check (≥ 90%) is needed only for the imagine-everything variant.
What a failure would mean
  • G2.1 fails on both seeds: the code does not steer the writer. The concept branches of S4 and S5 stop, and the project reports evidence against concept-level control at this scale.
  • G2.2 fails but G2.1 passes: codes work if you look at the answer, but the selector cannot be trusted alone. Search can still use it as a prior, but plain greedy results carry no claim.
  • G2.4 fails: the codes write the same thing. Decoder-free search is dropped, and only the grounded control remains.
  • G2.3 fails at depth H: search may look only as deep as the passing depth.
